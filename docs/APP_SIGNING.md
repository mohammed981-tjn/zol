# توقيع تطبيق zol

بصمة التوقيع هي هوية التطبيق عند أندرويد. نسخةٌ ببصمة مغايرة **لا تُثبَّت
فوق** المثبَّتة، بل تُرفض. لذا مفتاح واحد ثابت يُوقّع كل نسخة، إلى الأبد.

## البصمة الحالية

```
SHA256: 99:31:7D:3A:F7:77:AE:E1:38:FD:19:79:1E:69:7D:4D:
        A0:5F:D1:AE:C9:D7:96:E3:EE:C5:A1:42:6D:F0:98:7D
```

خطوة «التحقق من البصمة» في البناء تطبعها. **إن ظهرت غيرها فالمفتاح لم
يُقرأ**، والنسخة الناتجة لا تصلح للتوزيع.

## القيم الأربع

| الاسم | المحتوى |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | ملف `.jks` مرمَّزًا base64 في سطر واحد |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور المخزن |
| `ANDROID_KEY_ALIAS` | `zol` |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح (نفس السابقة) |

تُضاف في **Settings ← Secrets and variables ← Actions**.

## Secrets أم Variables؟

سير العمل يقبل الاثنين ويفضّل `secrets`، فلا ينكسر البناء بسبب خانة
خاطئة. لكنهما ليسا سواءً:

| | Secrets | Variables |
|---|---|---|
| التخزين | مشفَّر | نص مكشوف |
| العرض في الواجهة | لا يُعرض أبدًا | ظاهر بزرّ نسخ |
| الحجب من السجلّات | تلقائي | **لا** |

**Secrets هو الصحيح لهذه القيم**، فثلاث منها أسرار حقيقية. وحين تُقرأ من
`variables` يحجبها سير العمل يدويًا بـ`::add-mask::` ويطبع تحذيرًا — علاج
لا وقاية.

## ⚠️ فقدان المفتاح لا رجعة فيه

**أسرار GitHub للكتابة فقط**: بعد حفظها لا تُقرأ ثانيةً، لا منك ولا من
أحد. فتخزينها هناك **ليس نسخة احتياطية**.

ولو ضاع المفتاح فلا نسخة مستقبلية تستطيع تحديث ما على أجهزة المستخدمين —
لا حلّ إلا أن يحذف كل مستخدم تطبيقه ويثبّت من جديد.

احفظ القيم الأربع في مدير كلمات مرور. ولا ترفع ملف `.jks` إلى المستودع
أبدًا؛ `.gitignore` يمنعه عمدًا.

## توليد مفتاح جديد

للمشاريع الجديدة فقط — لا لهذا المشروع بعد أول تثبيت:

```bash
bash tool/make_keystore.sh
```

يولّد RSA-4096 صالحًا ثلاثين سنة، ويطبع القيم الأربع جاهزة.
