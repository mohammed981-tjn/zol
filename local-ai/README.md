# الذكاء المحلي — تقطير كاتب الإعلانات إلى الجهاز

## الفكرة

المنتج اليوم ينادي السحابة مرتين لكل إعلان: مرة ليكتب الكاتب ثلاث صيغ،
ومرة ليمنحها الناقد درجات ويرتّبها. الثانية أغلى مما تبدو — فهي تُنفق رموزًا
على تقييم نصٍّ سبق أن دُفع ثمن كتابته.

لكن كل تلك الأحكام محفوظة. `generation_logs` يحمل الموجز كما أُرسل،
و`ad_variants` يحمل الصيغ بدرجاتها ورتبها. هذه مجموعة تفضيلية لم تُصنع
للتدريب لكنها تصلح له: مدخلات من تجّار حقيقيين، وحكمٌ من الناقد نفسه الذي
يخدم الإنتاج.

التدريب على **المخرجات المرتّبة** يقطّر الكاتب والناقد معًا في نموذج واحد:
تمريرة محلية واحدة تحلّ محل تمريرتين سحابيتين — بلا تكلفة، بلا انتظار
شبكة، وبلا مغادرة بيانات التاجر جهازه.

## الخطوات

### ١. استخراج المجموعة

```bash
export SUPABASE_URL=https://fbbrkwragezhztffbvxf.supabase.co
export SUPABASE_SERVICE_ROLE_KEY=...        # لا تضعه في git
python3 export_dataset.py --out data/
```

ينتج `sft_train/val.jsonl` و`dpo_train/val.jsonl` و`meta.json` (يضم
البرومبتات الفعّالة ليطابق التدريبُ ما يراه النموذج في الإنتاج).

التقسيم بتجزئة `generation_id` لا بالعشوائية — إعادة التشغيل تعطي نفس
التقسيم، فلا تتسرّب أمثلةُ تدريبٍ إلى التحقق بين تجربة وأخرى.

أزواج DPO تُبنى من الأعلى درجةً ضد الأدنى، وتُستبعد حين يقلّ الفارق عن
`--gap` (١٫٠ افتراضًا): تفضيلٌ بفارق عشريٍّ ضجيجٌ لا إشارة.

### ٢. التدريب

يحتاج GPU — Colab يكفي.

```bash
pip install -U transformers peft trl datasets accelerate bitsandbytes
python3 train_lora.py --data data/ --model gemma --out out/ --dpo
```

الأسماء المختصرة: `gemma` (‏3-4b-it) · `gemma-small` (‏1b) ·
`falcon-ar` (‏Falcon-H1-3B، عربي أصالةً) · `qwen`.

ابدأ بـ`gemma` للقياس، ثم جرّب `falcon-ar`: هو المرشّح الأقوى للعربية
لكنه أقلّ نضجًا في أدوات التحويل للجهاز.

### ٣. القياس قبل التحويل

```bash
python3 evaluate.py generate --data data/ --model google/gemma-3-4b-it \
    --adapter out/sft --out preds.jsonl

export OPENROUTER_API_KEY=...
python3 evaluate.py judge --data data/ --preds preds.jsonl
```

المحكّم هو `ad_critic_system` نفسه، لا مقياس مخترع لهذه التجربة.
والمقارنة عمياء: يُقلَب ترتيب الاتجاهين في نصف العيّنات، وإلا كافأ
المحكّمُ الأولَ لكونه أولًا.

الخرج: متوسط المحلي، متوسط السحابي، ونسبة الفوز. **لا تحوّل النموذج قبل
أن ترى هذا الرقم** — التحويل والتكميم عمل طويل يُهدر إن كانت الفجوة واسعة.

### ٤. التحويل للجهاز

بعد أن يُقنع القياس:

- **LiteRT / MediaPipe** → `ai-edge-torch` ثم ملف `.task`، وتشغّله
  `flutter_gemma` على أندرويد وiOS والويب.
- **llama.cpp** → `convert_hf_to_gguf.py` ثم `llama-quantize Q4_K_M`.

## كم مثالًا يلزم؟

LoRA يعطي نتيجة معقولة من ~٥٠٠ مثال. دون ذلك يحفظ الأمثلة بدل أن يتعلّم
الأسلوب — والسكربت ينبّهك إن كانت المجموعة أصغر من أن تُدرَّب.

## ما لم يُختبر بعد

`export_dataset.py` مُختبَر منطقيًا ببيانات اصطناعية (التقسيم، غياب
التسرّب، عتبة الفارق، ترتيب الأهداف) لكنه **لم يُشغَّل على القاعدة الحقيقية**
بعد — اتصال Supabase كان منقطعًا وقت كتابته. `train_lora.py` و
`evaluate.py generate` يحتاجان GPU غير متوفّر في بيئة التطوير هذه.
